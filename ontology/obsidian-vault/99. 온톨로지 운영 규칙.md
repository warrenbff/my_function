# 온톨로지 운영 규칙

## 온톨로지 고도화 참고 자료

온톨로지 구조·계산 규칙·Neo4j 동기화·조회 API·챗봇을 고도화할 때는 [사내 온톨로지 구축 참고](../docs/사내-온톨로지-구축-참고.md)를 먼저 확인한다. 사용자가 2026-10-19 제공한 사내 구축 사례이며, 관련 원칙의 채택·수정 적용·보류 여부를 해당 설계에 기록한다. 원본의 완료 상태와 테스트 수를 현재 프로젝트의 상태로 인용하지 않는다. 이 참고 자료가 기존 사용자 진술·출처·시점·개인 규칙 채택 경계를 변경하지는 않는다.

## 데이터와 지식의 분리

- `개념` 폴더: 변하지 않는 객체 정의와 관계
- `프로세스` 폴더: 판정·계산 절차
- `결과물` 폴더: 특정 기준일의 판정 이벤트와 근거
- `10. 시범 실행`: 합성 데이터로만 동작을 검증하는 공간
- 과거 유사 사례: 현재 병목의 지속성과 해소 경로를 검증하는 비교 객체

## 증거 보존

결론 노트에 출처 URL만 붙이지 않는다. `주장 → 관측값 → 출처`를 별도 객체로 남긴다. 반박 근거도 삭제하지 않고 동일한 구조로 연결한다.

## 시간 보존

데이터셋과 판정 이벤트에는 반드시 기준일과 확인일을 쓴다. 새 결론이 나오면 이전 이벤트를 덮어쓰지 않고 새 이벤트를 추가한다.

## 기존 발굴 모듈의 승격 규칙

아래 순서는 기존 정량 발굴 모듈 내부의 설계다. 전체 세컨드 브레인이나 모든 조사 후보에 적용하는 사용자 채택 규칙은 아니다. 제품별 수급 조사와 현재 복기 경계는 아래 2026-09-28 규칙을 따른다.

`정량 점수 → 정성 병목 근거 → bottleneck_context → 기업 후보 → 가치평가 → 안전마진` 순서를 건너뛰지 않는다.

병목 확정 전에는 과거 유사 사례를 검색한다. 과거 사례는 현재 병목의 증명이 아니라 보조·반증 근거로 연결하며, 유사성보다 구조적 차이와 해소 경로를 함께 기록한다.

탐지 로직은 성공 사례만으로 검증하지 않는다. 미탐지 사례(false negative)와 반대 사례(false positive)를 동일한 기준일의 정보로 재생하고, 최초 실패 단계와 수정 전·후 결과를 [[프로세스/탐지 실패 분석]]에 남긴다.

실제 데이터가 들어오기 전에는 개념·프로세스·템플릿만 만든다. 빈 값의 결론 노트나 가상 근거를 실제 투자 지식으로 승격하지 않는다.

## 외부 원칙을 개인 철학으로 반영하는 규칙

- 외부 저자의 주장과 개인 복기를 별도 폴더에 보존하고 비교 객체로 연결한다.
- 출처 페이지 확인은 저자 서술의 확인이다. 인용된 성과·시황의 독립 검증을 뜻하지 않는다.
- 저자 원칙, 정리자의 비교 해석, 사용자의 채택 결정을 구분한다. 사용자 선택 근거가 없으면 채택 상태는 미정이다.
- 책 안에서 다른 기준은 출처별로 함께 남기며 임의로 단일 실행 규칙으로 합치지 않는다.
- 원칙의 시험 채택과 검증된 개인 규칙으로의 승격은 별도 단계다. 기존 개인 규칙의 반복성·반대 사례 조건을 유지한다.
- 과거 판단을 비교할 때 당시 가용 정보만 사용한다. 나중에 읽은 책을 과거 매수 근거로 소급하지 않는다.
- 채택·수정·철회는 새 이벤트로 남기고 이전 결정을 보존한다.


## 예외와 실행 가능성의 보존

- 숫자 기준은 적용 범위·기본 조치·예외·상충 설명·미확정 조건·채택 상태와 함께 보존하고 검색한다.
- 미확정 참고 원칙을 자동 실행 규칙으로 승격하지 않는다. 경고와 실행 지시를 구분한다.
- 신규 후보 선별과 보유 관리를 분리한다. 산식·데이터 부재는 0점이 아니라 산출 불가로 표시한다.
- 적용 사례: [[성상현 부부장/06. 스크리닝과 실행 해석 경계]].


## 2026-09-28 사용자 지정 최우선 경계

기존 문서와 충돌하면 이 절을 따른다. 근거: [[복기/진술/2026-09-28 직접 진술]] U06~U07.

1. **복기는 사용자 직접 진술·당시 사용자 작성 자료만으로 작성한다.** AI 추정은 `추정`이라고 표시해도 개인 기억 안에 넣지 않는다. 외부 사실은 별도 자료에 둔다.
2. 당시 사용자의 잘못된 믿음도 그대로 보존한다. 사실 확인·교정은 피드백에 둔다. 현재 회상·현재 의견과 당시 기록은 구분한다.
3. 모든 생각·감정·동기에는 진술 ID와 출처 위치를 연결한다. 원문을 찾지 못한 기존 인터뷰 요약은 보존 영역에 두고 원문 대조 대기로 처리한다.
4. 발표일·실제 열람일·결정일·기록일을 구분한다. 공개 정보만으로 개인 정보 상태를 채우지 않는다.
5. 결과 관측·원인 가설·교훈은 피드백, 외부 지식은 자료실/결과물, 채택 규칙은 투자철학, 실행 양식은 프로세스에 둔다.
6. 규칙에는 사용자 채택 여부와 효과 검증 여부를 각각 둔다. 시험 적용을 막기 위해 반복 검증을 선행 조건으로 강제하지 않는다.
7. 사용자 정정은 분석 가설보다 우선한다. 유명해서 하이닉스를 제외했다는 설명은 U04에 의해 부정됐다.
8. `자료실/기존 혼합 기록/`은 원문 보존 영역이다. 개인 성향 검색·집계에서 제외한다. 문서 내부의 옛 상태보다 이 영역 분류가 우선한다.
9. 기존 점수·상위 3개·3년 지속 조건은 과거 발굴 모듈의 설계다. 모든 기업 조사와 개인 투자에 사용자가 채택한 규칙은 아니다. 제품 단위 수급 조사는 점수 계산 전에도 가능하다.
10. 새 분석과 규칙은 이전 버전을 덮어쓰지 않는다. 이번 재분류 전 원본은 볼트 밖 ZIP 및 볼트 안 보존본으로 보존했다.

현재 방식은 Markdown과 링크를 이용한 수동 지식 구조다. 자동 시계열 수집·개인 사고 추출·매매·성과 검증이 구현됐다고 표현하지 않는다.
