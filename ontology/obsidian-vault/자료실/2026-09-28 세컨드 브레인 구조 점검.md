# 세컨드 브레인 구조 점검

## 목적과 결론

사용자 목적은 **개인 의사결정의 디지털 트윈 → 피드백 → 개인 투자프로세스 → 다음 기업 발굴·분석·결정 → 다시 결과 비교**의 반복이다. 기존 저장소는 산업 병목·텐베거 발굴 설계에 개인 복기와 외부 저자 자료를 덧붙인 구조였다. 방향은 일부 맞았지만, 복기와 분석의 경계·시간별 반복 연결·실제 기능 안내가 일치하지 않았다.

이번 작업은 문서 기반 기록 구조를 수정했다. 자동 발굴 엔진, 대화 자동 수집기, 포트폴리오 계산기, 수익률 검증기를 구현한 작업은 아니다.

## 점검 범위

변경 전 볼트의 Markdown 115개를 목록화했다. 핵심 지도·스키마·운영 규칙·복기 사례·의사결정·템플릿·발굴 절차를 내용 검토하고, 나머지를 포함한 전체 활성 문서의 제목·위키링크·폴더 구성을 기계 점검했다. 모든 기업·책·가격 수치와 원 거래 560행을 재검증한 것은 아니다. 기존 데이터 숫자는 그 출처의 기존 집계임을 표시했다.

## 현재 크게 다섯 영역

| 사용자 관점 | 실제 경로 | 인과관계에서의 역할 |
| --- | --- | --- |
| 복기 | `복기/진술`, `투자 사례`, `의사결정` | 사용자 원문으로만 실제 생각 복원 |
| 피드백 | `피드백/`; 기존 비교 일부 `투자철학/` | 예상·결과·지식 비교, 원인 가설과 정정 |
| 투자프로세스 | `투자철학/개인 투자 규칙`, `프로세스/` | 채택한 방법·절차·버전 |
| 다음 분석과 결정 | `기업분석/`, 사용자 결정은 `복기/의사결정/` | 규칙 적용, 정보 기준일, 실제 선택 보존 |
| 참고 지식 | `자료실/`, `결과물/`, `성상현 부부장/` | 외부 지식·사실·사후 연구·보존본 |

보조 영역: `개념/`은 정의 사전, `09. 병목 판정 체계/`는 기존 분석 모듈, `10. 시범 실행/`은 시범 데이터다. 기존 문서를 전부 이사하지 않고 진입점과 의미 경계를 정리했다. 따라서 물리 폴더가 딱 다섯 개로 줄어든 것은 아니다.

## 실제로 따라갈 수 있는 한 사이클

[[피드백/훈련 기록/TR-001 HBM 수급 예상]]에서 복기 → 피드백 → 새 지식 → 사용자 채택 → 규칙 → 다음 적용 → 결과 재비교를 한 번에 따라갈 수 있다.

현재 완료된 것은 규칙의 향후 적용 채택까지다. 실제 신규 기업에 적용한 결과와 수익 효과는 아직 없다. 개인 실패 원인은 미확정이어도 학습한 방법을 앞으로 적용할 수 있다.

## 원문 보존과 엄격한 복기 경계

- 변경 전 전체 볼트 ZIP: 프로젝트 `reports/second-brain-audit-20260928/vault-before.zip`.
- 기존 복기 Markdown 17개는 `자료실/기존 혼합 기록/복기/`에 바이트 그대로 보존.
- 기존 인터뷰 요약을 사용자 원 메시지와 이번에 대조할 수 없었으므로, 새로운 복기 본문에 확정된 사용자 사고로 옮기지 않았다. 내용 삭제나 거짓 판정이 아니라 출처 확인 상태의 분리다.
- 분석자가 제안한 ‘유명해서 배제’ 설명은 사용자에 의해 부정됐으므로 유지하지 않는다.
- 잘못된 믿음도 사용자 당시 생각이었다면 원문은 보존한다. 외부 사실로 교체하지 않고 피드백으로 연결한다.

## 아직 없는 것과 향후 검증 대상

1. FLNC·PoET의 기존 요약과 원 사용자 발화·화면의 문장별 대조.
2. 과거 거래별 실제 판단과 수량·손익·정보 인지 시점을 묶는 완전한 시계열.
3. 실제 새 기업 분석·규칙 적용·후속 결과 비교의 첫 사례.
4. 현재 작업 트리에서 삭제 상태인 `scripts/bottleneck.py`, `scripts/tenbagger_pick.py` 등 기존 실행기. 문서 연결만으로 복구됐다고 보지 않는다.
5. 자동으로 원문을 추출하거나 보존 폴더를 검색에서 배제하는 집행 장치. 현재 경계는 문서·양식·폴더로 적용하며 향후 자동화 시 별도 구현해야 한다.

## 확인 자료

`reports/second-brain-audit-20260928/migration-manifest.json`에 이전 파일 해시·보존 경로·이동 경로가 있다. `audit.json`에는 활성 문서 목록·제목·위키링크 점검과 보존본 해시 확인 결과를 저장한다. 가격·공시의 정답 검증 결과로 해석하지 않는다.

최종 구조 점검: 활성 Markdown 128개, 보존 영역 18개(원문 17개+안내 1개). 활성 문서의 대상 파일이 없는 위키링크·로컬 Markdown 링크는 0개이며, 보존 원문 17개 모두 이전 해시와 일치한다. 헤딩 앵커·외부 URL의 가용성·모든 사실의 정확성을 검증했다는 뜻은 아니다.

## 옵시디언 탐색 설정

프로젝트 루트 `.obsidian` 설정에서 기존 그래프 검색어가 `복기`여서 피드백·프로세스가 함께 보이지 않을 수 있었다. 현재는 `obsidian-vault` 전체에서 보존 영역을 제외하도록 바꾸고 화살표를 켰다. 북마크에 시작하기·TR-001·이 보고서를 추가했다. 기존 그래프 설정은 `reports/second-brain-audit-20260928/obsidian-before/`에 보존했다. 실행 중인 앱에서 화면 반영까지 직접 확인한 것은 아니다.

그래프의 화살표는 단순 문서 링크이므로 그것만으로 원인·결과를 판정하지 않는다. 인과관계의 설명은 시작하기와 TR-001의 단계 표·도식에서 읽는다.
